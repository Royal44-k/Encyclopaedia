# 山谷场景开发记录

2026-11-08 · 首次可玩样板

## 场景实现

同一个 Three.js 场景承载总览、桥位、上游、东岸裸土、温室访谈和试验台。八个地点沿用 v3 的 X/Z 锚点，地形计算 Y。拱顶温室与木桥各有一个永久实例。镜头移动和证据截图共享同一座桥、同一条溪流和相同的地标变换。

温室由金属肋条、分格玻璃、砖石基座、半穹顶门厅、左右侧翼及内部种植槽组成。西侧工坊有瓦片、木梁、工作台与陈列架。树屋的支柱、平台和楼梯连到地面。花园包括环形花圃、铺石支路、长椅、灯柱、喷泉、草坡和分层远山。主要资产由代码建模，地表、木材和石材使用程序生成贴图，树枝、曲面叶片、花朵和碎石使用实例化。概念图用于构图、材质和配色参照。浏览器画面来自实时三维场景。

东北水道经上游、东岸径流汇入口及桥下流入南侧池塘。当前轮次的下游为棕色，上游保留蓝绿色。雨前记录通过同机位的历史状态生成，生成后恢复当前状态。清除瓶子与安装覆盖物分别改变道具可见性及摆放状态。水色只随观察记录切换。试验托盘由渲染模块单独呈现，正式安装使用东岸现场的摆放判定。

## 已检查的画面和状态

- 在 Windows 上用无头 Edge 与 SwiftShader 打开 1440 × 960 的开发页面，检查总览。地形的规则条纹已消除，木桥、花环、主温室与东西两岸的相对关系可读。
- 用同一场景导出并检查 800 × 480 的桥位、东岸和上游记录。雨前及当前的桥位记录均可导出，当前记录中的瓶子在西桥头旁的石块间可见。东岸镜头的近处枝叶遮挡已处理，检查到的画面能看到裸土、浅沟及溪岸，交界处仍有几何简化。该次浏览器检查报告零页面或控制台错误。
- 单独运行 Node 场景检查，验证地标实例唯一、八个锚点存在、清理与覆盖物的可见性更新以及历史模式返回后恢复当前状态。用三个预设变换单独验证，裸土源头允许安装，非相关位置不允许安装，占路位置会触发阻挡。最终集成构建和主路径验证由集成记录单列。

## 仍需制作和验证

这批场景属于可走访的程序化样板。薄玻璃、溪面和近景植被仍有风格化处理。玻璃使用透明材质与角度高光，水面使用程序化色差与动态细纹。接触细节、泥水深度、植被分布和花圃物种还需要美术制作。现有角色为临时模型。捡瓶动画使用桥头的备用落点，场景没有独立的垃圾容器模型。树冠的末次调整使用由叶片组成的实例簇，作者的独立画面检查早于这一步，最终画面以集成截图为准。

交付为可编辑的运行时源代码。生产级 glTF/纹理资产包、角色表演、正式配音和课堂设备性能数据属于后续工作。本次无头浏览器用于场景与流程检查，未以其输出建立课堂帧率基准。
