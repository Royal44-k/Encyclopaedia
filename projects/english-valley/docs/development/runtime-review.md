# First journey runtime review

Reviewed Task 1 and the UI adapters against the v6.1 journey contract during integration. `npm test` in `app` passed all 19 tests. The reducer preserves the fixed no-cover baseline, keeps cleaning, modelling and installation distinct, preserves interview receipts and committed drafts, and rejects late run completions. The browser sequences below were traced through the integration code. The placement adapter shape and paused-model state were also reproduced with Node.

## Findings

- **P1 · Valid placement can never confirm with the unfiltered renderer result.** Reach the placement screen, put the cover over the source soil and confirm. The environment returns `zone` and `valid` alongside the three guard booleans. The renderer forwards that object and the UI spreads it into the context. A Node dispatch with this shape failed with `Unknown context key zone`; the same valid placement with only the three booleans installed successfully. Pass only `targetSurfaceAcceptsCover`, `placementBlocksRoute` and `coverOrientationValid` to the reducer. [UI](../../app/src/main.js) · [Renderer](../../app/src/world/renderer.js) · [Reducer](../../app/src/core/journey.js)
- **P1 · Restoring the model can display a result for an unfinished run.** Finish an unrelated-zone run, select source cover, start the next run, then pause or refresh during playback. The saved state correctly keeps `latestPosition=unrelated_zone`, `latestResult=no_difference` and `candidatePosition=source_cover_zone`. `restoreView` renders the candidate at full progress because an older trial exists. The tray then shows reduced runoff for the unfinished source-cover run. Restore a completed visual only when the displayed position matches the committed result. Label the previous result with its saved position when the learner previews another position. [UI](../../app/src/main.js) · [Renderer](../../app/src/world/renderer.js)
- **P1 · Failed writes can strand the current action.** Reject the journey storage write for `SESSION_OPENED`, then click Explore. `ui.started` changes before the commit and the entry button disappears. Reject `PAUSE_SAVED` or `TRIAL_CANCELLED` during an active trial. The UI invalidates the live callback before checking the write and can change the rendered scene while the committed trial remains running. Reject `TRIAL_COMPLETED` at the end of playback and the callback ends with no way to retry that completed run. Keep the current scene and callback valid until a commit succeeds. For a failed completion, keep a retry with the same run and command IDs. The store already retains stable IDs for its own pending retries, but cleanup and installation handlers supply new explicit IDs on each attempt. [UI](../../app/src/main.js) · [Store](../../app/src/core/journey.js)
- **P1 · Recovery can fail to preserve the only copy.** Seed the journey key with malformed JSON and choose Export from the recovery modal. The store preserves the raw value, but the exporter parses it again and throws. Export the raw string when parsing fails. When load failed because interrupted-trial recovery could not write, expose retry of `INTERRUPTED_TRIAL_RECOVERED` alongside export. [UI](../../app/src/main.js) · [Store](../../app/src/core/journey.js)
- **P1 · Saved transforms are applied before checking the scene binding.** Reopen a valid save from a different `session.layoutVersion` with a draft. The store loads such a save with no error because its event history is valid, and the ready callback applies its fields directly. Compare the persisted version to the active scene before applying any draft or installed transform. Check draft geometry for its own zone and preserve the original record for explicit recovery when the binding or pose is invalid. [UI](../../app/src/main.js) · [Environment](../../app/src/world/environment.js) · [Storage contract](../design/v6/first-journey-flow-v6_1.json)
- **P2 · A failed media write is later treated as a durable cache hit.** Fail writes to the media key while opening the bridge pair, then open it again. `capture` caches each frame before writing it, so a later call can succeed from memory and allow an observation to be recorded without a durable image. Publish the cache after the media write succeeds. If an optional cleanup or installation image fails after the action commits, retain the valid action and expose the missing frame as pending. [UI](../../app/src/main.js)
- **P2 · Deferred cleanup lines can miss an ordinary return to the bridge.** Leave cleanup feedback pending while its speaker is absent, then return to the bridge in fieldwork. `walk` uses `cast_arrived` only when no domain arrival is pending. A successful fieldwork `MOVE_ARRIVED` stays in the same node and queries a trigger the global cues do not declare. Query `cast_arrived` after that arrival and retain entry dialogue when arrival also changes the node. [UI](../../app/src/main.js) · [Cue contract](../design/v6/first-journey-flow-v6_1.json)

During review, the integration switched resume to `scene_resumed`, restored the saved anchor with a separate continuation action and reopened the model camera. Follow-up source checks also found a raw-export fallback, matching-position model restoration and a post-arrival cue query. The findings above record the original reproductions for regression checks in the final browser build.

## Final integration follow-up · 2026-11-08

The reviewed source addresses all seven original findings. Placement sends only the declared guard booleans. Model restore shows a completed tray only for a matching candidate and labels the last saved result by position. Entry, pause and cancellation wait for commit, and failed trial completion retains its command and run IDs for retry. Malformed raw saves can be exported. The ready callback checks scene versions and placement geometry before applying saved transforms. Media cache entries are published after their write succeeds, and arrival queries deferred cast cues.

The new unresolved exit saves the learner's question only after `UNRESOLVED_SAVED` commits, displays it in the terminal view and retains the resume point. The dynamic renderer import displays the initial interface before WebGL setup and handles import errors through the existing fallback. These paths were checked in source.

- **P2 · An unavailable image can block edits to a saved picture note.** In a clean Edge context, seed a valid explanation that references `record.bridge.current_round.v1` and omit the media storage key. Continue the visit and open the picture note. The only option is the already selected blank placeholder, so choosing it produces no change event. Saving rejects the unavailable source and leaves the saved reference unchanged. Retain a selected unavailable-source option so the learner can explicitly choose the blank frame or a replacement. This was reproduced against the existing preview bundle. [Picture editor](../../app/src/main.js)

The source fix keeps the unavailable ID selected under a visible label and leaves the blank option available. Selecting the blank option now changes the value and clears the stale source through the existing editor handler.

The Edge regression passed against production bundle index-U85a2Duk.js. The stale ID was selected and labelled unavailable. Choosing the blank option with the keyboard emitted one change event. Saving cleared the source ID, retained the learner's original caption and committed exactly one new revision. No browser page errors were captured.
