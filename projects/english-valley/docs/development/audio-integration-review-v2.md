# 声音接入审阅 · v2

2026-11-08。审阅对象是实际主界面、场景声音运行器和录音索引；浏览器录音资产的语义、情绪与发音质量仍需要单独试听。

## 源码审阅

首次进入在可信点击处理器开头调用 `unlock()`，然后才等待录音索引和移动。场景使用“出现次数、节点、地点”共同标识，普通设置或对白收条引起的DOM重绘复用标识。移动前取消旧对白，抵达后依据新地点与人物到场条件重新取词。重听按钮显式调用重播接口，不依赖自动队列是否已经播过。

声音设置迁移与学生旅程状态分开，旧版默认 `sound:false` 不会让新版本无意中继续全程静默。之后的v2静音选择应被保留。对白、音乐、自然声使用独立开关和音量，总静音另设。页面隐藏时由运行器暂停，pagehide/pageshow提供补充处理。

发现并交给主集成处理的具体问题：

1. 保存暂停先触发终场渲染，再立即停止对白；如果最后不再渲染，保存后的新旁白会被取消。应在取消移动后重新同步终场声音，或将这次提交合并为一次渲染。
2. 新旅程只停止对白，主界面尚未开始会跳过声音同步，导致旧地点背景音乐留在新入口。应明确进入新的arrival音乐场景。
3. 设置改变会替换原来的打开按钮，关闭对话框时原焦点节点已失效。应记录按钮的动作并在原节点断开时寻找新的同动作按钮恢复焦点。

图片/设置对话框目前继续播放正在进行的场景声音。这可以是设计选择；需要保持字幕可回看，不能将听完音频作为操作资格。语音不能因声音关闭阻挡学习流程。

## 浏览器验证方式

[browser-audio-v2.mjs](../../app/scripts/browser-audio-v2.mjs)在独立Edge上下文运行。脚本追踪实际音频文件解码、AudioBufferSource启动及各声源的非零PCM峰值，另从最终混音端测静音，因此不以界面上的“正在说话”文字作为播放成功的唯一证据。

覆盖自动入口顺序、普通重绘不重复、重听、总静音、独立对白/音乐、场景音乐变化、五个不同的录音身份、保存场景旁白、移动端声音按钮、新旅程音乐和旧偏好迁移。原生音频错误、意外控制台错误与页面错误分别记录。五身份检查包括Noor、Rowan、Mei、Sam和旁白；它不冒称五名人物均为真人演员。

已在录音资产准备完毕的生产构建 `index-Ds2Kg1PA.js` 上实测，8组检查全部通过，未捕获意外控制台或页面错误。主集成与此代理的独立执行均返回通过；代理会话67136已经结束，没有遗留运行中的测试进程。

## 最终冻结前补充修复

上述通过后，主集成进一步发现两处边界：操作区复用试验音乐文件但应有更轻的增益；重听前一句时，不应丢弃尚未听完的下一句。

运行器现已在同一文件URL下更新场景标识和目标增益，保留已有音乐声源连续播放；重听改为优先播放请求句，再接续不同的未完成当前句和剩余队列，去除重复项。新增两项Node回归后，音频运行器合计11项测试通过。

浏览器脚本也补充了操作区实际 `audioMusic=placement` 的断言，避免只看相同文件URL就误以为场景增益已切换。这两项修复之后的最终构建由主集成负责重跑并补记哈希；前述8组结果明确对应修复前的 `index-Ds2Kg1PA.js`，不冒称新构建已完成验收。
