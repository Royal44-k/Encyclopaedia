# English Valley · 同一世界的美术与场景契约 v3

日期：2026-11-06。用途：正式模型生产、镜头制作和后续实时渲染的共同验收依据。**这是设计约束与拟定生产规格，不代表模型、状态系统或浏览器性能已实现。**

用户已选择：**图1作为世界总览；图2、图3作为同一世界的局部视角。** 此决定更新《concept-directions-v2.md》中“等待选择”的历史状态。三张概念图获认可的是视觉方向和体验意图，不是已经精确对应的三维投影。本文以图1空间身份为主，将其余两图的镜头感和操作体验统一进一套场景；不再把三图解释成三个独立世界，也不沿用 v0.1 的五个语言技能房间。

概念参照：`assets/concepts/v2/mistlight-conservatory.png`（图1）、`along-the-living-stream.png`（图2）、`rainworks-valley.png`（图3）。本轮已逐张检查图像。下文凡涉及世界尺寸、位置、资产制作及验收阈值，均是本项目提出的约定，而非从概念图测量出的事实。

## 1. 视觉身份与三图统一规则

主基调为**精致自然主义的花园山谷**：保留鼠尾草绿、细金属玻璃温室、温暖木材、环形花圃、石径、微雾群山和宁静的整体构图；增加能在学生视角近看时成立的结构、材质、接触、使用痕迹和动作。游戏质感来自这些要素共同成立，不能用高饱和 bloom、全屏景深或大量粒子代替。

| 项目 | 三图中实际观察到的差异 | 统一后的强制规则 |
|---|---|---|
| 主温室 | 三图都有弧顶、圆形前厅和侧翼，但跨度、框架间距、连接关系不同 | 按图1建立一份主模型和立面比例；图2/3重新取景，不能各造一套温室 |
| 工坊 | 图1在温室左前方、距东侧溪流较远；图3把工坊放大并拉近河岸施工区 | 工坊留在西侧原位。工具由工坊领取并带到东岸；局部操作镜头不保证同时出现大面积工坊立面 |
| 桥 | 图1在右前水路，图2/3桥的横向构图、栏杆细节不同 | 只保留一座主木桥及同一套栏杆、桥面、桥头；以相机角度产生构图变化，不能复制另一座桥 |
| 水路 | 图1右侧溪流汇入前方池塘；图2/3更接近宽河段 | 保留“东北来水—东侧溪流—东南桥位—南侧池塘—下游出口”的连续关系；近景水宽由同一几何决定 |
| 裸土与径流 | 图1异常位于右侧；图3裸土移到左侧工坊附近 | 主调查裸土固定在东岸。局部取景可改变画面左右，但不能改变世界方位和上下游关系 |
| 天光与灯具 | 三图湿度、暖光和温室灯光状态不同 | 视为不同环境时刻的参考；同一次观察的镜头切换使用相同时间、天气、曝光和灯具状态 |
| 人物、植被、道具 | 图2有近处学生，图3有施工工具；植物布置不完全一致 | 使用同一角色与植被资产库。角色和可移动道具可以移动，建筑、永久树木、道路不能随镜头挪位 |

可微调：远景植被密度、非叙事碎石、云雾形状。不可随镜头微调：地标变换、岸线、桥头连接、温室门的位置、证据位置、已修复物、灯具编号。看不清的地标通过镜头或遮挡处理解决，不能偷偷搬到镜头前。

## 2. 一份坐标和拓扑，多个镜头

采用右手坐标，1 单位 = 1 米，+Y 向上；本项目另约定 +X 为东、+Z 为南，地图北方为 −Z。原点在主温室大厅地面中心。glTF 的米制和 +Y 向上来自规范；东南方位属于本项目约定。资产前向与相机朝向分别处理，不用“模型朝南”推导镜头朝向。[glTF 2.0 坐标与单位规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)

以下是供首次可编辑空间灰模使用的**建议锚点（X、Z，米）**，不是已锁定工程测量。Y 由连续地形高程 H(X,Z) 和资产落地基准决定。灰模阶段可整体调整一次，但必须同时更新总览和全部局部镜头；确认布局后写入同一版本的场景清单，不允许逐镜头保存另一套地形。

| 稳定地点 ID | 建议锚点 X,Z | 空间身份与不可破坏关系 |
|---|---:|---|
| `loc.greenhouse` | 0, 0 | 中央主温室；圆形前厅朝南，侧翼接主厅；参考主厅占地约 20×12 米，尺寸仍须用人物尺度验证 |
| `loc.treehouse` | −11, −12 | 温室西北后方；楼梯真实连至地面道路，不从总览到近景改变树屋楼层或支撑树 |
| `loc.workshop` | −18, 9 | 温室西侧偏南；连接西侧石径，承担 C2 材料检查与修复操作 |
| `loc.flower_ring` | 0, 20 | 温室前方环形花圃；是定向参照，不是独立测验房间 |
| `loc.upper_stream` | 23, 2 | 东侧溪流、主径流汇入口上游；需能与下游对照，不能落在同一混合水段 |
| `loc.bare_bed` | 28, 12 | 东岸局部裸土/花床；经可见浅沟至约 23,18 的汇入口，坡向不能倒置 |
| `loc.stream_bridge` | 21, 25 | 东南主木桥；建议桥面跨 X 方向，西桥头约 17,25，东桥头约 25,25；端点最终贴合岸坡 |
| `loc.exit_path` | 7, 41 | 南侧返回/离园道路；连接花园主路，不与水流出口混作同一设施 |

辅助空间：喷泉保留在温室右前侧；矩形草坪和长椅在西南；下游池塘约在 16,32，独立水流出口沿南侧继续离开场景。以上位置只约束相对关系，喷泉循环水不能暗中充当溪流来水解释。

必须成立的连接关系：

```text
水路：东北上游 → loc.upper_stream → 径流汇入口 → loc.stream_bridge → 南侧池塘 → 下游出口
径流：loc.bare_bed 的坡面 → 可见浅沟 → 同一个径流汇入口
步行：入口/离园道路 ↔ 花环环路 ↔ 温室 ↔ 西侧工坊 ↔ 树屋
支路：花环环路 ↔ 西桥头 ↔ 主木桥 ↔ 东岸调查小径 ↔ 裸土/上游观察点
```

屋顶雨槽、雨桶、溢流管各有可追踪去向。雨桶满后不能让水凭空消失；若设施尚未完成模型，不能先画一条看似已接通的有效排水路径。水面和湿痕方向服从坡面与水路，视觉上不出现上坡漂浮、穿过实心岸壁或在桥面流动的错误。

“同一世界”指共享权威布局、对象身份和持续状态；允许按区域分包加载、多套相机和分层渲染。它不要求所有内容合成一个不可编辑 GLB。总览、实地观察和操作界面必须引用同一地标实例。

## 3. 对象身份、案例状态与时间

地点 ID 按上表固定；永久实例用明确对象 ID，例如 `obj.bridge.main`、`obj.greenhouse.main`、`obj.runoff.east_bed`、`obj.workshop.bench.01`、`obj.light.path.01`。`assetId` 表示可复用资产种类，`objectId` 表示世界中的特定实例，不能混用。实例身份保存在场景清单和导出元数据中，并做唯一性校验；不能依赖加载时生成的 UUID、网格数组下标或可重复的显示名称。glTF 的 `name` 本身不要求唯一，因此不能承担存档主键。[glTF Indices and Names](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#indices-and-names)

| 状态层 | 必须保存的内容 | 切镜头/换案例时的规则 |
|---|---|---|
| 世界版本 | 布局版本、资产版本、稳定对象 ID、已发生操作 | 不因进入局部镜头重新生成地形或物件 |
| C1 径流调查 | 已观察来源、采样位置与时刻、局部措施、模拟输入与结果 | 已放置覆盖物/植物带保持存在；雨量和观察条件可回看 |
| C2 修复与再用 | 原物身份、检查记录、拆换部件、再用材料来源、修复结果 | 回总览仍看到修复物；材料不会在背包和工作台同时无限复制 |
| C3 傍晚照明 | 灯具身份、开关/朝向/遮光部件/使用计划、观察条件 | 白天灯具实体保留；到傍晚使用同一配置，不以切场景恢复默认强光 |
| 学习记录 | 事实、猜想、来源、方案、修订与倡议 | 与天气特效分离；换镜头不清空，教师演示重置需明确范围 |
| 临时交互 | 当前高亮、鼠标悬停、摆放预览、未确认选择 | 可取消；未确认预览不得写成已完成措施 |

区分三种时间：

1. **观赏环境预览**：改变光照、云雾、季节外观，用来欣赏或查看同一地点。界面明确“环境预览”；不推进课堂事件、植物生长或修复进度。退出后还原实际观察条件。
2. **故事时间**：雨前、雨后、傍晚和后续复查。推进时保留对象状态，并记录发生顺序。新植栽可以显示为已种下的小苗；不能切到夏季就宣称生态已恢复。
3. **简化实验时间**：C1 用明确降雨输入运行可重复的教学模型。比较前后措施时固定雨量、起始土壤/含水假设及必要随机种子；显示“简化模型”，保留实验记录。测试结束可以回到真实世界当前状态，不能把测试副本污染为未经确认的永久结果。

同机位对照期间冻结曝光和纯观赏天气，或显著显示条件不同。不能用阴天换晴天、提高曝光、移除棕色后处理，制造“水质改善”的假证据。清除瓶罐只改变垃圾状态；覆盖土壤、拦截径流只影响其对应的局部机制；任何一次操作都不能使整条河、所有生物和全部植物立即恢复。

教师重新开课采用明确的“新建课堂副本/重置指定案例”语义，默认保留原记录；状态迁移需报告无法对应的对象，不能静默丢失。以上是拟定行为契约，尚未实现存档系统。

## 4. 镜头连续性与操作可读性

| 镜头 | 用途 | 拟定规则 |
|---|---|---|
| `cam.overview` | 图1总览、定位和返回 | 优先验证高位长焦透视；必要时评估正交镜头。主温室、花环、右侧溪流和桥保持图1识别关系，不把整片山谷做成漂浮玩具岛 |
| `cam.field_bridge` | 图2实地访查 | 从桥/下游东南侧向温室方向观察，同一桥进入中景；学生视高以人物实际身高定，不强行复制生成图的桥宽和河宽 |
| `cam.action_east_bed` | 图3东岸措施操作 | 看清手、工具、地表和汇水方向；将图3操作气质放入东岸真实位置，西侧工坊可以只在远景或画外 |
| `cam.workshop` | C2修复 | 在同一西侧工坊靠近工作台；工具握点、零件接触、材料前后状态可见 |
| `cam.evening_path` | C3照明比较 | 在同一路段固定观察位，记录灯具参数与环境时刻；不能把不同镜头的亮度当成公平比较 |

相机从总览进入地点时，先明确目标，再沿可理解路径过渡；保留桥、温室或花环至少一个方位参照。禁止穿墙、穿树干、冲进玻璃和无理由大幅翻转。短距离移动可以平滑；大距离跳转用明确定位加短淡变，不制作漫长失控飞行。支持减少动态效果的直接切换，期间任务和输入焦点不丢失。

若正交总览切到透视，须按目标在画面中的尺寸和中心点对齐，再过渡或淡变；不能插值成畸变的中间投影。相机方案只是视图：不能更改物件尺度、遮挡顺序或存档状态。地点标签锚定真实世界坐标；被遮挡时隐藏、聚合或给方向提示，不永久穿墙覆盖全部证据。

## 5. 资产生产与可操作结构

主温室、桥、工坊、树屋、调查岸坡和近景工具按本视觉方向制作或深度改造。通用 low-poly 包可用于灰模、远景和非关键小物；未经近景审核的素材不得充当主建筑、可操作工具或主视野植被。风格统一不仅是换色：轮廓、倒角、木板厚度、纹理尺度、磨损程度、叶片层次和结构细节都必须一致。

每项可交付资产包含：可编辑源文件；运行时 glTF/GLB；纹理与色彩空间清单；真实尺寸、轴向、原点和包围盒；来源/授权与改造记录；材质变体；LOD 或无需 LOD 的理由；碰撞/点击代理；可交互部件与接口；动画列表；资产预览及导出版本。导出后重新打开核对，不能以 DCC 软件里看起来正确代替运行时验收。

| 资产类 | 必须能拆分和验证的部分 |
|---|---|
| 温室 | 玻璃、框架、基础、门、可见内部、雨槽和排水出口；玻璃不能是整栋不透明青绿色壳 |
| 桥与石径 | 桥面、支撑/桥头、栏杆、步行面；脚步不悬空，道路接地不靠厚阴影掩盖 |
| 工坊/修复物 | 工作台、抽取部件、损坏/已修复变体、再用材料；保留同一物件轮廓和身份 |
| 植被 | 主树冠层次、近处叶片/枝条、地被与苗木；风摆枢轴正确，根不滑动，苗木不等同成熟植被 |
| C1工具与材料 | 铲、托盘、覆盖物、植物带预览与实放件；握持点、放置面、有效边界明确 |
| C3灯具 | 灯罩、发光部、灯杆、照射方向、遮光或转向部件；外观发光与实际照亮周围是分开的受控量 |

采用米制校验物体大小；门、台面、桥栏杆、工具握柄用同一人物参照检查。建筑原点服务于定位，门铰链、工具握点、灯罩转轴各有局部枢轴，不能全部强行归到世界原点。碰撞代理和点击代理可低复杂度，但不得使学生点击空白处得到远处物件。

工具动画按 `idle / inspect / pick_up / use / place / cancel` 等明确动作组织，具体动词按物件实际用途裁剪。每段给出时长、可中断点、接触事件和完成事件；世界状态由完成事件或明确确认写入，不由动画播放到某一帧“猜测成功”。手掌不穿柄、脚不滑步、铲头接触正确表面；取消操作不复制或遗失材料。独立物体可分别控制动画，不需要把整个世界塞进一条动画时间线。[Three.js AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)

Blender 导出时须记录版本与设置。UV 接缝、平面着色边缘可能在 glTF 导出中拆分顶点，因此统计导出后的数据；不能把 Blender 面板数字直接当浏览器负载。自定义属性可用于传递本项目元数据，但必须校验实际导出结果。[Blender glTF 手册（4.4 版本）](https://docs.blender.org/manual/en/4.4/addons/import_export/scene_gltf2.html)

证据边界：本次 Blender 官网正文抓取受限，以上基础事实由官方手册搜索返回的段落核对；未验证某个已安装 Blender 的导出器 UI。生产时需锁定实际工具版本再检查一次导出流程。

## 6. PBR、纹理和光照约定

以下色彩管理来自 Three.js 官方文档；材质观感和验收场景是本项目约定。颜色贴图和数据贴图必须分清，线性光照计算后再输出显示色彩，避免重复转换。[Three.js Color Management](https://threejs.org/manual/pages/color-management.html)

| 输入/输出 | 约定 |
|---|---|
| Base color / emissive PNG、JPEG | 标记 sRGB；不把强方向性阳光或高光烘进 base color |
| Normal / roughness / metalness / AO 等数据 | 使用非颜色数据语义，通常 `NoColorSpace`；不能按颜色贴图做 sRGB 解码 |
| HDR 环境、光照贴图 | 按实际文件编码标记，线性 HDR 常用 Linear-sRGB；不能只看扩展名猜导入结果 |
| 工作与输出 | 线性工作空间；显示输出 sRGB；后处理链仅在正确末端做输出转换，避免多次色调映射 |

每种材质都有统一参考球和实尺寸平面：深色金属框架、木材、湿/干石材、土壤、叶片、玻璃、水面。先在中性环境检查，再放回艺术天光。木材不呈金属，石头不全部像蜡，玻璃不是无反射的空气，水面不全是金属镜面。粗糙度与细微法线负责质感；近景轮廓、板厚和明显接缝需要几何，不能全部靠法线贴图假装成立。

纹理分辨率按最近允许观察距离、屏幕占比和重复使用方式决定；先确定纹理的真实尺度，再选尺寸。禁止全资产统一 4K，也不能以大贴图补救错误 UV。图集接缝、重复图案、mipmap 远景闪烁和湿/干材质切换在三个主镜头都要检查。LOD 必须保留可识别轮廓与交互接口；远景可以简化小细节，桥头、门和证据不能消失。Three.js 提供按距离切换层级的基本机制，但层级和切换点需用实际镜头验证。[Three.js LOD](https://threejs.org/docs/pages/LOD.html)

温室近景优先评估物理 transmission；它比单纯降低 opacity 更适合薄玻璃的反射/透射关系，但也有更高逐像素成本。因此按可见面积和设备实测决定使用范围，不能为全场所有透明面无差别启用高级效果。远景的简化版本必须保持框架轮廓、主要反射和内部可读性。[Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

玻璃与水面须在重叠、掠射和进出镜头时检查排序、深度和反射；不能用永远置顶或整片双面渲染掩盖错误。玻璃外景反射与周边环境方向基本一致。风叶、雨滴和水流共享当前风雨条件，不让静止树冠旁出现暴雨横飞。

静态间接光与接触暗部可评估烘焙，日照方向、移动人物、开合门和可操作灯具使用能响应状态的方案。不能把白天长阴影永久烘进地面后再直接改成夜晚；不能让烘焙暗影与实时阴影叠成黑斑。不同时间如采用预烘焙光照组，应明确对应条件及转换策略，关键局部光变化仍需真实响应。曝光、色调映射、环境强度和雾属于统一渲染配置，不给每个资产私自加“补光滤镜”。

## 7. 可核查的质量门槛

正式制作按“空间灰模 → 主建筑与近景材质样板 → 同一场景三镜头 → 操作状态 → 代表设备实测”推进。图像生成结果只作概念目标，不能作为完成以下门槛的证据。

| 验收项 | 必须提交的证据与通过条件 | 退回条件示例 |
|---|---|---|
| 同一世界 | 同版本场景的俯视布局和三个镜头；永久地标 ID/变换一致，路径、水路连通 | 近景出现第二座桥，工坊移位，温室侧翼改变，岸线换成另一条河 |
| 建筑与尺度 | 主温室、桥、工坊近景及人物尺度参照；构件接合、门和道路可达 | 仅用几何方块代替主建筑，栏杆/木板无厚度，人物无法穿门 |
| 材质 | 中性灯光样板与艺术灯光实景；各材料仍可区分，纹理尺度一致 | 全场塑料般高光，石材金属化，湿地只靠全屏滤镜 |
| 玻璃/水 | 三镜头及掠射角检查；框架稳定、透明排序可接受、岸线和流向成立 | 后方玻璃盖住前方物体、河水穿岸、池塘在近景突然加宽 |
| 光照 | 晴/阴、雨后湿润、傍晚灯开关至少覆盖；同条件比较曝光固定 | 关灯但附近照度毫无变化，夜里保留烈日影，使用 bloom 冒充照明 |
| 交互动作 | 操作、取消、完成、返回总览完整录屏；手/工具/对象接触可信 | 点击立即换一张完工图、工具穿模、取消后材料丢失或复制 |
| 持续状态 | C1措施、C2修复、C3灯具设置跨镜头、跨案例、存读档对照 | 返回地图恢复损坏模型，切夜景清空 C2，换季等同生态治愈 |
| 解释一致性 | 雨前/雨后与措施前/后的同条件记录；结果说明局部机制和限制 | 捡瓶子让整条溪流立刻清澈，以水色宣称实际水质合格 |
| 课堂使用 | 投影/桌面文字与证据辨认、键盘/触控等价操作、减少动态模式检查 | 证据被景深模糊，必须快速精准拖拽，镜头动画导致读不完或晕眩 |

渲染验收画面应标注场景版本、相机、时刻、天气、曝光、设备和分辨率。离线 Blender 美图可作为材质参考，但最终通过依据必须包含实际浏览器输出；不能将离线渲染、生成图或视频预渲染描述成实时 3D。

性能不预先承诺任意“60 FPS”“手机全开”或全场面数上限。先选择真实课堂设备和浏览器，记录下载量、解码/上传时间、纹理内存估计、draw calls、帧耗时分布及输入响应；在温室玻璃大面积入镜、雨中植被、工具操作、夜间多灯等代表场景测量，再制定档位。降级优先减少远景细节、反射精度、阴影分辨率和非关键粒子；不能删掉证据、改变水路、移除交互反馈或让教学结果变化。

本文已明确设计合同与待验收项；尚未声称完成模型制作、实时渲染、课堂可用性验证或性能达标。
