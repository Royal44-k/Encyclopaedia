# v6正式开发准备度审查 · 工程与完整体验

2026-11-07。独立读取制作总案、场景执行约定、对白索引、v3地形与美术契约、T03及溪流段、T08、视听导演稿和现有素材清单。本轮判断基于设计文件，没有运行课件、模型、声音或设备实测。

## 判断

v6足以开始共同世界灰模、内容工具和关键交互预研，也足以确定完整项目的叙事方向。它尚不足以让十二章同时进入精模、正式录音和全量程序制作。主要缺口已从“故事讲什么”变成“同一份设计怎样被不同工种一致执行”。

已有文件清楚区分试验与实施、日期与重玩、原件与快照，这是重要基础。之前审阅说没有重要规划问题遗留，指的是所检查的叙事/教学问题已回答；不等于现在已经拥有可执行内容数据、经验证的交互模型和全部生产资产。

下面的补充可由设计者依据现有方向直接确定，无须重新向用户询问已确认视觉。技术框架的小版本、目录组织等可留给实际工程阶段，不在此制造审批。

## 优先补齐的具体合同

### P1 · 从台词引用到场面图

[对白索引](dialogue-reference-index.json)明示它不是可执行对话，并包含表格台词与51个行内分支引用。当前字段有说者、英语、表演提示与源文件，尚无统一的进入条件、可用选择、后继节点和结束节点。若工程师按编号顺播，T08会先播放愿意陪伴，再播放独处；T03会把约好回访与立刻调查都演出。

每个可制作场面至少需要：`sceneId`、入口、可用角色、`nodeId`、条件、台词引用、显示给学生的行动/意图选择、下一节点、一次性写入事件和出口。学生示例台词仍是支架，不能自动读成玩家已说的话。行内条件变体要提升为独立条目，并保证每个允许的选择均到达可继续或可保存结束点。

优先为第一条可玩旅程制作完整场面图，其余十一章保留设计稿，随生产逐章冻结。无需现在给每个背景闲谈增加复杂状态机。

### P1 · 定义何时发生了事，以及重播不会发生两次

[场景约定](story-state-and-staging.md)已经写清哪些内容保存，但仍需一个共同的事件提交规则。例如播放T03S.034不能本身使措施完成；重听同一句也不能再扣材料。操作确认与存档失败时，世界和叙事不能一边已完成、一边未完成。

建议采用以下最小事件合同，字段名称可由工程实现调整，含义应固定：

| 事件种类 | 何时提交 | 必须留下的事实 |
|---|---|---|
| 观察 | 玩家确认该观察卡/画面已打开 | 位置、记录时刻、条件、来源；不自动保存未听见的NPC心理 |
| 清理 | 目标物被有效收取、操作确认 | 对象ID、之前与之后状态；不改变水色结论 |
| 模型试验 | 一次试验完成 | 模型版本、输入条件、方案版本、结果类别 |
| 实施 | 条件核对、现场放置并确认完成 | 采用哪一方案、实际对象、位置、实施状态；与模型记录关联 |
| 表达作品 | 作者主动保存 | 文字/录音/图卡、使用范围、关联证据；不自动判定内容正确 |
| 回访约定 | 选择日期/观察点并保存 | 谁、哪里、何时、拟观察什么；尚未执行 |

每个改变世界的事件拥有唯一身份，重复接收不能重复执行。相机移动、重听、暂停和重看影片不提交新的世界事实。中断恢复以最后确认状态为准，未确认预览可恢复或取消，两者都不能暗中记作成功。

### P1 · 溪流模型需要可审阅的输入—结果表

[溪流第三场](episodes/T03-stream.md)给出了科学边界，但尚未定义覆盖物究竟对哪片区域产生哪一种定性结果。当前地形文件只有路径名和建议锚点。程序员如果自行写“放任何绿植就清水”，仍可能产出符合表面故事顺序、却违背教学含义的功能。

首条样板建议只做覆盖物一种措施，明确一个同等降雨预设、裸土区域、径流路径和可覆盖范围；植物成熟、复杂水流及多措施组合留后续。设计稿给出可审阅的三种情境：未覆盖、覆盖有效目标区、放在与目标径流无关位置。分别规定可见的土粒路径和结果类别，保持条件相同；不输出测得浓度或净化率。布局灰模确认后再把区域名绑定实际几何，不能先写死世界坐标再单独改地图。

覆盖物实际进入当前山谷后，只能证明“已放置”；后续观察须有新的明确时段和记录。样板可以结束在“实施完成、待复查”的可信状态，现实延伸通过课堂后续回看继续，而非演出成功代替现实证据。

### P1 · 第一条样板应包含完整教育经历

总案提出T01、T02、T05、T08四个艺术/技术样板，能检验触感、声影、纸样和人物表演；它们本身无法验证整个课件的入口、英语交流、调查、行动、保存与回访是否顺畅，也没有完整覆盖环保主线。

建议保留这些局部验证，同时确定一条完整可玩的第一旅程，见下节。先把这个旅程从开场做到可恢复的收束，再扩大章节与精细资产数量。

### P2 · 明确课堂模式的首版边界

T03的双人信息差、T08真人角色扮演和T11交换试映，尚未指定同屏、分设备或联网同步。若开发默认实时联网，会多出账号、房间、断线同步、音视频与个人数据等大量工程；如果默认双方看到同一信息，信息差又会失效。

首版建议明确为单设备本地课堂：投屏教师引导、同设备轮换/角色卡和单人预写角色三种使用方式；隐藏卡通过分别展开或教师分发纸卡实现。真人交流在课堂发生，系统保存作者主动提交的成果。多设备协作作为后续独立需求评估，不能被“互动课件”自动推导成多人在线游戏。

### P2 · 生产资产需要冻结清单和最少交付包

[素材清单](../../../assets/ASSET-MANIFEST.md)仍主要是概念图、低模候选和占位音；六位正式角色、主建筑、近景工具与表演尚未生产。美术契约很详细，但没有第一旅程的“必须制作/共用/可以先用公共样件”清单。直接并行发包容易重复做桥、错配手部尺寸，或一次完成全部角色后才发现镜头不需要。

第一旅程至少冻结：地形/水路与桥；可辨温室外观；东岸花床与浅沟；观察照片和记录册；覆盖物、搬运与放置动作；实际参与的角色近景；来源清楚的短对白和声音。其余地标按统一布局显示合格远景轮廓。每项给资产ID、实例ID、源文件、枢轴、交互状态、所需动画、近看距离和验收镜头。未定成本的数据可在灰模后确定，不先凭空承诺面数或帧率。

### P2 · 语言交流与流程推进要分开

T03需澄清路线，溪流段需作解释，当前尚无统一规定“说过/写过”的判定与故事下一步的关系。不要让自由文本关键词充当理解判分，也不要让学生只能按固定英语按钮完成所谓对话。

建议：程序只验证客观动作、记录引用和作品是否保存；表达是否充分由学生、同伴或教师查看。允许继续场面，明确保留“说明尚未提交/可以补充”的状态。教师推进只改变课堂进度，不篡改学生是否已理解。已提交的短表达可再次编辑，修改后产生新版本而非覆盖历史证据。

### P2 · 课堂硬件基线与失败时的可用行为

当前正确地没有承诺任意设备流畅，但正式美术批量生产前需要一个实际课堂代表设备和浏览器测试记录。设备尚未锁定时可以先做灰模与一处高保真样板，不宜把全谷大透明温室、多角色面部和大量植被都按最高规格完成后再压缩。

样板应同时检查：低帧率时仍能点选、音频未加载时字幕可继续、镜头中断不丢焦点、保存失败明确提示并允许导出作品、刷新后恢复最后确认的动作。这里要求可见行为，不预设具体存储库或监控服务。

## 建议的首条端到端可玩旅程

设计名称可沿用“地图上没写的那一站”，由现有内容裁剪，不另造世界或第十三章。

| 段落 | 当前内容来源 | 首版需要的真实参与 | 完成后留下什么 |
|---|---|---|---|
| 到访与一项偏好 | T03开场 | 问朋友想看什么，在两个路线入口中作选择；不先显示双方全部信息 | 路线约定与已知时段 |
| 桥边发现 | T03及溪流第一场 | 看同机位记录，选择先观察或先清理 | 各自真实发生的顺序，清理不改变水色 |
| 追问与对照 | 溪流第二场 | 向Mei问时间/目击范围；看上游和花床路径 | 至少一条判断、一条证据和一个未知 |
| 试一种措施 | 溪流第三场 | 同等条件下比较覆盖前后或不同位置 | 可重复的试验版本与定性结果 |
| 采用或暂存 | T03S.031–034 | 选择提案暂存，或实际搬运、放置并确认 | 世界已实施状态与模型快照分开 |
| 向朋友说清 | T11表达方式的有限使用 | 三幅记录图加短说明/可选录音，不先制作完整视频编辑器 | 可被同伴理解的说明，待修改也可保存 |
| 回访与离开 | T12表达方式的有限使用 | 选观察点、写/说下一次想查什么，回到地图 | 作品与回访约定；刷新后可恢复 |

这条旅程建议按两课组织，教学时长由走读确定，不预先承诺课堂一定完成。桥边调查可以是共同活动，创作和声音谜题之后仍按原十二章继续扩展。角色数量按实际场面冻结；不为缩小样板而把所有角色对白改给同一个万能NPC。

T01/T02/T05/T08的局部艺术样板仍有价值：它们分别验证后续最难的材质操作、声影推断、纸张形变与情感表演。前两类可与完整旅程的基础系统共用；纸样和面部表演的验证可并行，不阻塞第一条故事的灰模开发。

## 开发开始前应形成的最小交接物

1. 第一旅程的场面图与分支出口，引用稳定台词ID，正文不再让程序员猜顺序。
2. 事件与存档字段合同，标出世界、模型、学习记录和历史作品各自写入者。
3. 一种环境措施的定性规则表、固定对照条件及对应场景区域。
4. 第一旅程冻结资产清单与镜头清单，并为后续四个艺术样板留接口。
5. 同屏/投屏/单人模式的具体输入与信息显示方式，避免默认联网或默认AI理解自由语言。
6. 一份可实际走读的课堂脚本：人物愿望是否被学生听懂、下一步是否有理由、表达是否改变同伴理解。

这六项补齐后，可以把设计作为正式的第一批开发依据；全量十二章逐批沿同样合同进入制作。无需等待文本绝对完美，但需要在真实样板中检验“好玩、可信、可教、可保存”能否同时成立。
