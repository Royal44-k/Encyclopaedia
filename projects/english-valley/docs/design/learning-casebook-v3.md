# English Valley · 案例与交互设计 v3

2026-11-06。视觉已由用户确认：图1全景地图，图2/3同一世界内的场景视角。案例设计深化稿；未完成试教或正式课件实现。本文替代旧五站通关设定，语言材料见 `docs/content/narrative-corpus-v3.json`，来源见同目录登记表。

## 体验主张

学生是受邀协助山谷开放日的青年观察小组。他们面对的是一个有人劳动、有人休息、需要维护的小世界。任务不是找到“坏人”，而是问清发生了什么、哪些解释有证据、怎样改善而不把负担转嫁给别人。

三个案例共享地点、人物、材料和操作后果：第一案调查水路，第二案为改进方案准备合适材料，第三案安排开放日夜间使用。学生的方案并不决定山谷突然繁荣或毁灭，而是改变具体对象和人的使用体验。

### 人物与合理立场

| 人物 | 知道什么 | 关切与盲区 | 学生需要做什么 |
|---|---|---|---|
| Mei，园丁 | 花床翻土、降雨前后的工作安排 | 希望完成补植，也需要维护人员；不是水质专家 | 礼貌追问时间、地点和观察，不先归责 |
| Rowan，巡护员 | 固定位置照片与巡查记录 | 记录有空缺，不能代表所有降雨 | 区分记录、推断和未知 |
| Sam，工坊维护员 | 材料来历、维修记录、部件用途 | 维修时间有限，不能凭外观保证旧材适用 | 阅读材料说明，询问条件，说明取舍 |
| Amina，社区志愿者 | 开放日实际使用路线与收尾工作 | 希望节能，也关心慢行访客与工作人员 | 倾听需求，测试路线，修订简单化建议 |
| 学生同伴 | 各自取得的信息与不同初步判断 | 容易先入为主，也可能提出关键反例 | 轮换发言与角色，互相澄清而非抢答 |

人物信息都是原创虚构，不冒充真实访谈或专家结论。

## C1 · The stream after the rain

**驱动问题：Why is the stream cloudy after rain, and what can we reasonably do?**

一场雨后，木桥边出现浑浊水流，岸上有瓶罐。初看很容易把全部问题归于垃圾。学生有权先清理垃圾，但复查仍能看到从花床方向流来的泥水；世界因此提出下一问，而非弹出“答错了”。

### 调查中必须分清的证据

| ID | 载体与地点 | 能支持 | 不能支持 |
|---|---|---|---|
| C1-E01 | `loc.stream_bridge` 同机位雨前/雨后照片 | 两个记录时点的外观不同 | 具体污染物、健康风险或所有时段的水质 |
| C1-E02 | `loc.upper_stream` 与桥边的同轮观察 | 这次观察中两处有差异 | 上游永远清洁，或差异只有一种原因 |
| C1-E03 | `loc.bare_bed` 裸土、浅沟和水路 | 存在可能把土带向溪流的路径 | 已经证明全部泥沙只来自这里 |
| C1-E04 | `loc.greenhouse` 园丁访谈 | 翻土时间、盖土措施未完成及工作条件 | 园丁“造成全部污染”或故意破坏 |
| C1-E05 | 树屋巡查日志，缺一日记录 | 现有记录中的变化与空白 | 没有记录就代表没有问题 |
| C1-E06 | 桥边瓶罐近景与清理前后 | 可见垃圾数量可减少 | 水变清、生态恢复或水可以饮用 |

环境机制依据为 ENV01/ENV02；山谷事件、照片、时间线和模拟结果均为教学创作。

### 核心交互与分支

1. **比较，不只是找高亮点。** 学生在同一观察位切换照片，选择“位置一样但时间不同”或“同一轮观察、位置不同（分别记录拍摄时刻）”，随后写一句观察。标签只有在接近或启用辅助提示时出现，不让线索四处闪光。
2. **访谈有追问。** 选择“什么时候注意到变化”“哪里先出现变化”“你的依据是什么”，得到不同信息。直接问“为什么你弄脏小溪”会得到园丁合理澄清，并可重新措辞；不扣好感值，不锁死任务。
3. **证据板不是拼图答案。** 将线索放在支持/尚不能确定区域，并解释一条关联。允许不同证据组合；系统可检查是否引用有效线索，论证充分性由教师/同伴审阅，不伪造自由文本判分。
4. **先行动也可继续学。** 清走瓶罐立即改变桥边物件；未覆盖裸土和径流保持原样。学生看到两种问题并存，再修订假设。
5. **操作有空间后果。** 植被带放在模型汇流路径旁可减少模型中的土壤移动；放在无关位置则不能取得同样效果。雨水花箱没有接到屋顶雨槽时，水会绕开它。可撤销、移动、重试，且有等价点击与键盘操作。
6. **比较控制条件。** 测试前保存方案版本，两个版本使用相同模拟雨量、相同时长与初始土壤条件。若条件改变，界面明确提醒“这些结果不能直接比较”，允许重新运行。

模拟以定性教学规则为主：显示泥沙移动路径与结果类别，不能编造测得的真实 mg/L、精确去除率、鱼类恢复率或健康指数。已建立植被的效果需要以“模拟数周后”明确表示，不能把刚插入的苗当作成熟缓冲带。实际现场布局需专业评估。

### 课堂成果

每组提交一段解释：一个判断、两类证据、一个限制、一项措施与复查方法。基础句框与自由表达并行，允许“目前还不确定”。不以选完所有物件作为理解证明。

## C2 · A second life, for the right purpose

**驱动问题：Should we repair, reuse or replace it—and who will look after it?**

开放日前，工坊里有旧木箱、待修座椅、来源不明的涂漆木板和一批新材料。第一案促成补植与后续养护计划；花圃另需两只花箱，社区访客仍需休息座位。这些花箱不自动作为径流处理设施。学生不能把所有旧东西改成花箱，也不能因为“新”就判为浪费。

### 证据和任务

| ID | 载体 | 重要信息 | 语言动作 |
|---|---|---|---|
| C2-E01 | 材料卡 | 木箱来历已知；待检查，不能仅凭外观确认适用 | 描述状态、请求检查 |
| C2-E02 | 维修记录 | 座椅有一处松动部件，维护员安排检查 | 区分 broken / loose / worn 及事实范围 |
| C2-E03 | 来源标签缺失的木板 | 涂层和以往用途未知 | 明确“I don't have enough information…” |
| C2-E04 | 社区留言 | 有人需要在花圃旁坐下休息，不愿座椅被拆走 | 转述他人需求，避免把留言当工程结论 |
| C2-E05 | 任务与维护表 | 需要两只种植容器；维护工作须有人承担 | 分工、比较数量与工时；游戏资源不是市场报价 |
| C2-E06 | Sam本轮检查记录 | 对象ID、拟定用途和本轮检查结果；默认与替代情境分别生成 | 根据本轮记录决定可选方案 |
| C2-E07 | 学生确认后的成果记录 | 原对象、实际用途、维护安排与复查计划 | 描述已经发生的改造，区别计划与成果 |

学生先旋转查看物件，读标签/维修便条，询问维护员，再把材料分成“检查后可考虑使用”“保留原用途并维修”“信息不足先不使用”。检查由剧情中的维护员完成；游戏不要求学生现实中处理旧漆、切割或维修承重家具。

### 两条都可成立的方案

- **方案甲：保留并维修座椅，把检查适用的木箱改为容器。** 能回应休息需求、减少新购物件，但要安排容器维护。学生须写明谁检查、谁每周复查。
- **方案乙：保留并维修座椅，选用适合用途且能够维护的新容器。** 有明确需要和维护安排时，不得因为使用新物品自动扣分。教师可另启“座椅检查后不宜继续使用”情境；该情境须同步更换检查记录、对白和方案，不能沿用默认结果，并须安排适用的替代座位。

模型操作：拆装经过检查的非危险模块、为容器放置内胆/标牌、调整位置使通道保持通畅、选择维护责任人。视觉反馈是具体物件有了用途、座椅保留或替换、通道能否通行，不是全景突然开花。

知识依据 ENV03：减量和再用是重要策略，但做法要考虑材料和情境。本案不提供产品生命周期的虚假碳排放计算。英语区分 reuse 与 recycle；本项目用完整物件做新用途叫 reuse，不把它一概叫 recycle。

### 反思

“A useful object can carry a memory, but a memory cannot prove that an object is safe.” 是本项目原创的进阶讨论句。学生可以不同意保留某件物品，但需回应使用者和维护者的理由。

## C3 · Enough light for everyone

**驱动问题：How can we use less unnecessary light without leaving people behind?**

白天任务结束，山谷转入傍晚。同一条石径、同一座桥与已安装物件都在原处。学生发现部分灯仍亮着，最直接的想法是全部关闭；访谈却表明志愿者还在整理工具，慢行访客也需要看清返回路线。

### 证据和操作

| ID | 载体 | 需要判断 |
|---|---|---|
| C3-E01 | 开放日收尾安排 | 谁还需要照明、在哪一段、何时结束 |
| C3-E02 | 三个固定观察点的视图 | 光是否照在路径上、是否溢出到植物/窗户/天空；这是视觉模型，不是专业照度测量 |
| C3-E03 | 志愿者与访客访谈 | 慢行、停下来阅读路标和工作收尾的需要 |
| C3-E04 | 灯具控制说明 | 遮光罩、朝向、定时/手动控制可以组合；并非一键全关 |

学生在虚拟模型里调整灯具朝向与遮光罩，分别测试“有人工作”“访客慢行”“无人使用”三种状态。灯过早熄灭时，人物停下请求帮助，不跌落受伤；学生可调整控制规则并重试。镜头和界面亮度保持可读，不通过近乎全黑制造困难。

可接受的方案包含：保留必要路径与工作区照明；关闭无人使用的装饰灯；减少不需要的光外溢；设置合适控制并保留人工操作。只写“Turn off all the lights”不足以回应所有证据。科学依据 ENV04，仅作为负责任户外照明的一般原则，不把本模型当作学校电气施工或照明合规认证。

开放性问题：谁来决定“足够”？我们询问过哪些人，又遗漏了谁？这要求学生用英语澄清需求、表达让步、提出条件，而不是说出唯一道德答案。

## 三案如何形成教育闭环

1. **发现与思考**：观察变化，保留初步解释。
2. **访查与线索**：询问不同人物，辨认事实/意见/不确定；每条证据保留地点和时间。
3. **方案与实践**：学生选择、说明理由、实际摆放/调整模型对象；操作与解释同时存在。
4. **结果与修订**：同条件测试，分析没有达到预期的部分；改变方案后保留版本，不抹掉思考过程。
5. **现实迁移**：在校园选择一处可观察的小问题；比较条件差异，不照搬山谷答案。教师提供照片可替代学生拍摄。
6. **意识与号召**：写一段“我如何改变了判断”的反思；向明确的同学/社团发出可行邀请，约定一次跟进。

原主案建议 3×40 分钟＋一周跟进；C2/C3 各作为一课时拓展或完整工作坊的后续章节。不要将三个案例全部强塞进一节课。课时、词汇量与写作篇幅需以本班水平试教校准。

## 趣味性与机械感的具体边界

- 提供观察、比较、追问、搬动、旋转、拼装、走访、试验、记录、修订等不同动作；每个动作必须产生与案例相关的信息或状态变化。
- 允许不同路线、不同有效方案、延后决定和承认未知；不以收集全部发光点或猜中固定按钮替代推理。
- 奖励是看见自己的方案留在世界中、听见人物具体回应、对照前后记录。删除无意义连胜、点击金币和随机夸奖。
- 场景中设少量可选发现，如旧维修铭牌、雨槽水声、夜间路标；发现提供人物背景或解释，不强迫学生为装饰跑遍地图。
- 主界面保持安静；短字幕、可重听访谈、随需词义、句框和全景定位属于帮助，不因使用而扣分。
- 教师可以暂停环境动画、点名某条证据组织讨论；学生不因操作速度慢而失去表达机会。

## 语言丰富度与评价

核心语言行为按任务递进：描述→比较→礼貌提问→转述→猜测→因果解释→建议→条件与让步→评价限制→反思与邀请。基础路线用短句和句框完成同样的认知任务；进阶路线要求更准确地表达不确定性与取舍，不能靠堆生词提高难度。

客观信息提取可以检查来源匹配、数目、先后、语义差别；开放表达采用教师/同伴量规：英语可理解性、证据适配、方案与修订、现实邀请的具体性，各0–2分。解释合理的不同表述不能因没有命中预设句子而失败。词数只是辅助，不能伪称自动评价思想深度。

## 发布前内容质量关卡

每个语料单元有稳定 ID、任务用途、地点、原创/引用类型、语言功能、事实依据、审校状态。无来源的事实、未经许可的整段转载、自动语音未试听、缺答案依据的封闭题都不得标为课堂正式版。权威来源支持某一词义或语法规则，不等于该机构审核过我们的完整对白。

本轮做结构与语言内部审查；仍需英语教师按实际教材版本复核并试教。对外状态写清“内容深化稿/已核对来源”，不做“绝对零错误”的不可验证承诺。
